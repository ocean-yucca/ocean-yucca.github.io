Syntax
# Variable syntax
variable "variable_name" {
  description = "varaible description"
  type        = string # variable type
  default = "default_value"
}
        	
# Provider syntax
provider "provider" { # google, aws, azurerm
  project = "project_id"
  region  = "region_name"
}
        	
# Resource syntax
resource "RESOURCE_TYPE" "name_for_terraform" {
  name                    = "name_for_GCP"
  # RESOURCE properties
}
        	
# Output syntax
output "output_label" {
  description = "label name"
  value       = resource.property
}
        	
# Module syntax
# module in Terraform is a folder
# define blueprint in a module
# use the blueprint defined in the module
module "name_for_terraform" {
  source           = "./mymodule" # module name
  instance_name    = "vm-1" # vm name on GCP
  instance_zone    = "us-central1-a"
  instance_network = google_compute_network.mynetwork.self_link
}
Comman Files
  • provider.tf, configures the cloud provider
  • variables.tf, declares variables, not assign values
  • terraform,tfvars, set up values for varabiles
  • module folder, define resuable blueprint
  • main.tf, define resources
  • outputs.tf, define what terraform output will show
State
  • .tf file -> real infrastructure -&gr; backend state, one-way
  • A shared backend state lets multiple developers safely manage the same infrastructure without stepping on each other
    • Everyone sees the same current infrastructure
    • State lock, when multiple developers run terraform apply at the same time, only one apply can run at once
    • Consistent drift detection, someone changes infrastructure manually, another developer runs Terraform later will detect the changes
    • Support CI/CD pipelines
    • Role-based access control, allow some developers plan and others apply<
